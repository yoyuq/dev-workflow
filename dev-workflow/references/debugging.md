# 重现、定位与修复

输入：失败的用户行为/验收条件、代码状态、日志、最近变化、已有尝试。先检索适用的错题记录，重新核实其版本和场景，不照搬旧结论。

1. 找到能暴露失败的最小重现。区分产品缺陷、测试错误和环境故障；先确认观察到的是同一个问题。
2. 读取相关实现和调用链，列出可检验假设及支持/反对证据。每次改变一个关键因素，不连改多处后猜测哪处奏效。
3. 修复根因，并在原失败场景验证。需要回归保护时添加会在旧实现上失败的行为测试；检查必要的边界和相邻路径。
4. 清除临时诊断代码，复查最终改动与结果。没有新证据时停止原样重复，记录已排除假设和最小下一步。
5. 将未解问题记为 unresolved，推测记为 candidate；只有修复前后证据支持才记为 validated。证据的有效范围不能扩大为“永远不会再犯”。

这是本包的通用指南，参考了 [Matt Pocock skills](https://github.com/mattpocock/skills) 和 [Superpowers](https://github.com/obra/superpowers) 的公开调试方法，并非声称安装了这些仓库的另一个原版调试技能。
