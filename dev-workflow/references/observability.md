# 查看运行与定位故障

2.11 的工作流服务首页使用图形化只读看板：首屏显示目标、进度、异常和任务依赖，点击节点查看详情。沿用 [service.md](service.md) 的启动方式，默认在服务器本机 `http://127.0.0.1:8765/` 打开。输入控制目录 auth.token 中的令牌；不要把令牌放进 URL、项目或截图。远程访问使用已配置的 TLS 代理或 SSH 转发，界面本身不会配置公网。

普通 Codex / Claude Code 对话使用 [会话流程图](session-view.md)：AI 登记节点、打开本机预览并在阶段变化时更新。无需服务入队，也不会另起模型。2.11.1 本机会话预览不展示令牌表单；AI 打开连接入口后，同浏览器的刷新、首页导航和新标签页自动恢复。页面标注“会话回报”和最近回报时间，验证依据由当前会话记录，不能视为控制器独立验收。

以下独立控制器模式中，已安装 Skill 不代表服务已启动。服务启动后，仅显示已通过服务入队的运行；它不会扫描或导入任意历史目录，也不迁移旧 pins。默认每 3 秒读取一次状态；自动刷新不触发任务执行。浏览器后台标签可能被限速，关闭页面不会收到浏览器通知。

## 动态执行图

图从当前有效计划与运行事实生成，每 3 秒更新，不是固定的开发步骤模板。任务节点同时显示稳定的模块目标和变化的当前动作：后者来自当前尝试向总控发送的公开 progress 消息，最多展示 280 字，主图只显示两行。没有回报时明确提示等待；重试不会沿用上一轮动作，停止或完成后显示控制器记录的状态。消息时间和尝试编号在节点详情中。

总控收到 change_request 后，图上显示分析反馈或等待计划生效。只有通过既有边界校验的修订才会改变拓扑：新增准备任务带有版本标记，新增依赖线加粗；点击“计划 rN”可查看原因和依赖的前后变化。新任务加入会增加总数，因此进度比例可能下降，不代表已集成结果丢失。

当前重规划允许在原目标、范围及预算内添加准备任务、调整未完成任务依赖；不支持任意删除节点或改写已确认的总目标、验收。详见 [replanning.md](replanning.md)。同一响应中的节点、依赖、版本和任务计数来自同一份数据库状态；总控独立于看板持续执行。

2.11.5 增加执行动效：执行节点轻微呼吸，已完成前置任务到当前执行节点的连线朝前流动，状态更新和计划重排短暂过渡。刷新复用节点，不重启动画。完成、受阻和待执行保持静止；动画不是进度计时器。图下方可暂停动效，系统“减少动态”默认生效，页面隐藏和节点离屏也会停下循环；用户可明确在本页面开启。

点击“动效演示”可查看六步模拟流程，用“下一步”手动推进；开启动效时也会自动切换。始终标明模拟，不运行任务或写入服务数据，模拟摘要不能导出。点击“返回运行”恢复实际记录及原选择、筛选和滚动，并刷新真实状态。

## 排查顺序

1. 从顶部下拉框选择运行。看整体进度和异常提示；颜色、图标和节点短标签一起显示状态。
2. 图中的实线是任务依赖，虚线是里程碑依赖。并行任务在同一层；缺失依赖或循环会提示异常。筛选只突出匹配节点，保留完整关系。
3. 点击节点打开详情。故障任务可直接“查看错误日志”；分支、提交和重试收在“分支与执行记录”中。检查通过、进程正常退出、任务集成是不同状态。
4. 展开“日志与事件”可选证据、搜索当前窗口或切换事件/消息。可关闭“跟随末尾”避免阅读时滚动。自动刷新保留展开状态和键盘焦点；Escape 关闭详情。
5. 人工问题通过顶部异常入口或交付验收节点查看，答复仍走原人工答复协议。复制定位链接方便回到同一任务；“更多”中可导出诊断摘要、启用通知或暂停刷新。摘要包含当前状态、最近事件与已打开的日志窗口，它不是完整日志备份。

页面显示的是观察到的现象，排查建议来自明确的故障类别，不代表已经证明根因。不在看板里修改计划、重置预算、重新派工或代替人工确认。业务代码、固定验收和旧运行状态保持原职责。

## 数据范围

- 概览最多展示最近 100 个运行；时间线最近 200 条、消息最近 100 条；证据列表最多 300 项，达到边界会提示。
- 单个日志窗口最多 64 KiB；文本取末尾，进程/审阅记录先提取允许字段，再在上限处截断摘要。大日志有截断提示，不读取任意文件路径。下载范围与当前视图一致。
- 工作者输出在运行中刷新到磁盘；process.json 的最终耗时/退出码在退出后生成，UI 不把缺失值当零。
- 启用备用入口后，日志目录也包含每次 provider 调用及额度续跑的进程、错误和事件记录；实施者、独立审阅与总控使用同样的证据入口。嵌套记录不重复算成新的实施尝试或汇总进程耗时。
- 模型事件只展示允许的事件类型、工具类别与退出结果；原始模型消息和推理正文不进入该视图。检查日志/错误输出为不可信文本，使用纯文本渲染。常见令牌模式与控制服务令牌会脱敏，但这不是任意秘密识别器。
- 浏览器提醒需点击开启并获浏览器允许，只提醒连接期间后续状态变化。没有邮件、微信或其他外部推送，也没有服务器告警队列。

新增只读 API 均要求 Bearer 鉴权：`GET /api/observe`、`GET /api/observe/{job_id}`、`GET /api/observe/{job_id}/logs/{artifact_id}`。artifact_id 是服务生成的不透明标识；客户端不能指定本地路径。现有 `/api/runs` 和 `/api/events` 保持兼容。网页静态资源公开但不带项目数据，访问令牌只存内存。

## 设计参考

- [GitHub Actions 日志](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs)：按任务和失败步骤查找日志、搜索日志窗口。
- [Langfuse Trace View](https://langfuse.com/changelog/2025-03-19-new-trace-view)：层级与时间线共同辅助定位；本看板采用简洁事件时间线，不是完整 span 追踪器。
- [LangSmith Observability](https://docs.langchain.com/langsmith/observability)：运行记录关联故障调查与状态提醒。这里复用本地证据，无需接入该服务。
