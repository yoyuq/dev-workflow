# 后端验证矩阵

选择与本次改动有关的行，使用项目已有工具和隔离环境。以公共接口和可观察行为为准，不为私有实现细节写脆弱测试。

| 变更 | 应取得的证据 |
| --- | --- |
| API 新增或变更 | 请求与响应符合契约；有效输入、关键无效输入及错误语义被验证 |
| 用户或租户数据访问 | 授权用户可访问；无权限、跨用户/租户访问被正确拒绝 |
| 业务状态变更 | 合法转换成功；重要非法转换被拒绝；失败不留下错误中间状态 |
| 数据迁移 | 用代表性的旧结构和隔离样例数据升级；验证兼容和约束；按项目需要检查回滚或向前修复 |
| 队列、回调或可重复操作 | 覆盖重复投递、失败、重试终止及有意义的幂等行为 |
| 外部服务 | 超时/错误处理验证；区分 mock/contract test 和真实集成测试 |
| 全栈联调 | 使用真实本地后端跑通相关前端流程，并验证重要失败反馈 |
| 性能相关修复 | 保存改动前后可比的测量条件与结果，不只根据代码推断变快 |

测试依赖缺失时说明具体缺口及影响。不能通过删除断言、把失败改为跳过或只保留成功 mock 来制造通过。

按需查证的来源：

- [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)：接口授权、输入校验和错误处理。
- [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)：资源与权限边界。
- 具体框架、ORM 和数据库的当前项目版本官方文档。
